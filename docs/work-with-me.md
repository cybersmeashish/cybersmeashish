# Work with Ashish

Bring a business process, a security decision, and a defined scope. The starting conversation should establish which outcomes matter and what evidence is needed.

## Collaboration formats

| Format | Useful starting problem | Proposed deliverables |
| --- | --- | --- |
| Security transformation discovery | Priorities and ownership are unclear across teams or technologies | Scoped process map, dependency inventory, current/target evidence, and prioritized decisions |
| AI and application architecture review | An assistant, API, retrieval path, or tool can access sensitive operations | Threat model, action-authority map, design review, and bounded test plan |
| Sovereign infrastructure and landing-zone review | A service needs explicit jurisdiction, administrator, key, supplier and recovery boundaries | Boundary register, local-dependency map, approved-flow contracts and environment-specific acceptance gates |
| Disconnected security workshop | Detection, identity, updates or recovery depend on external connectivity | Local-autonomy assumptions, controlled-transfer design and a scoped exercise plan |
| Cloud security design review | Workloads span accounts, regions, suppliers, or disconnected sites | Identity and flow boundaries, operating assumptions, and validation gates |
| Post-quantum readiness workshop | Cryptographic dependencies and supplier constraints are unknown | Inventory schema, ownership gaps, compatibility questions, and research plan |
| Framework adaptation | A standard or control catalog needs to fit a real industry process | Tailored control-evidence matrix, accountable roles, and review triggers |
| Research or engineering collaboration | A question needs reproducible implementation or independent evaluation | Agreed method, artifact, baseline, result record, and contribution credits |

These are collaboration scopes, not fixed-price packages or claims of previous client delivery. Timing, fees, responsibilities, confidentiality, and acceptance criteria are agreed for each engagement.

## Start the conversation

[Open a collaboration request](https://github.com/cybersmeashish/cybersmeashish/issues/new?template=collaboration.yml).

Provide a **non-confidential** description of the business process, the decision you need, the desired output, and timing. Do not include credentials, customer data, private infrastructure, exploit details, or contractual material in a public issue. Confidential technical review belongs in a separately agreed private channel.

## Evaluate the work first

Inspect the [selected repositories](https://github.com/cybersmeashish), run a local reference test, and read its limitations. A useful engagement produces decisions and evidence that your team can review and maintain.
