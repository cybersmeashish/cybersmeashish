# Industry work map

These workspaces connect a shared security method to sector-specific decisions. They define the material I intend to develop and the public reference work a collaborator can inspect. They do not assert previous client delivery.

| Workspace | Core process | Connected technical work |
| --- | --- | --- |
| [Government](https://github.com/cybersmeashish/government-security) | Public-service authority and accountable cyber capability | National framework, sovereign landing zone, disconnected operations, Sovereign AI |
| [BFSI](https://github.com/cybersmeashish/bfsi-security) | Transactions, customer access, resilience and cryptographic dependencies | Application authorization, AI tool controls, cloud boundaries, PQC inventory |
| [Oil & Gas](https://github.com/cybersmeashish/oil-gas-security) | OT and supplier interfaces, local security, safe operation and restoration | Disconnected operations, identity and update dependencies, evidence and recovery |

The [fourteen industry decision maps](https://github.com/cybersmeashish/ashish-vciso-repo/blob/main/industry-decision-maps.md) provide additional starting points. Expand a sector into its own maintained repository when distinct evidence and a sustained research program justify it.

Each sector contribution should connect: **business process → authority → threat or failure → control → test → evidence → leadership decision**.
